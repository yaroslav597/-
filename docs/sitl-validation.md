# Проверка ArduPilot SITL — 10 ноября 2026

Реализована и проверена цепочка React → FastAPI → pymavlink → ArduPilot SITL. Миссии не только принимаются по MISSION_ACK, но и читаются обратно, после чего сравниваются с сохранённым планом.

## Окружение

- Windows, Python 3.12.16, pymavlink 2.4.50.
- Нативная Windows-сборка из официального каталога [CopterStable](https://firmware.ardupilot.org/Tools/MissionPlanner/sitl/CopterStable/), скачанная 10.11.2026.
- Версия, сообщённая AUTOPILOT_VERSION: 4.7.3, firmwareType=128. Название каталога не подменяет версию, полученную от симулятора.
- SHA256 ArduCopter.elf: `D440DF2672199B4B7A62E49983060E18A333B3F1F8886B2D67D1E0F929F054C5`.
- MAVLink: TCP 127.0.0.1:5760; system=1, component=1.
- Старт: 55.755000, 37.590000, 150 м над уровнем моря; режим STABILIZE.

## Как сравниваются команды

Служебный Home с номером 0 принадлежит ArduPilot и исключается из сравнения полётных команд. Количество элементов проверяется с учётом Home. Для координатных команд учитываются эквивалентные frame=3/6 и округление координат до 2 единиц ×10⁻⁷ градуса. Допуск параметров и высоты — 0,001 с дополнительным относительным допуском 10⁻⁶ для float32. Для координат относительный допуск отключён.

Проверяются используемые Copter поля: например, для TAKEOFF — высота, для смены скорости — speed. Неиспользуемые yaw/pitch и поля, которые ArduPilot нормализует, не становятся ложными расхождениями. В частности, при чтении были получены frame=3 вместо отправленного 6, frame=0 у DO-команд и служебные значения param3/param4 у LOITER/LAND.

Успешное чтение и совпадение — разные результаты: операция чтения может завершиться успешно и вернуть `matches=false`. Различия показываются оператору по номеру команды и полю.

## Повторный запуск

Общий запуск теперь использует Linux SITL в Ubuntu WSL; для него требуется предварительная сборка ArduPilot в `~/ardupilot`. Текущая [инструкция запуска](../backend/README.md#подключение-sitl). Описанные выше результаты относятся к прежней Windows-сборке.

Из корня проекта:

```powershell
# Общий запуск Linux SITL в WSL, backend и React в фоне.
.\start-local.cmd
```

В интерфейсе выбрать «Backend / MAVLink», дождаться подключения и Home, затем «Загрузить в автопилот» и «Проверить миссию на борту». Отдельная наземная станция или MAVProxy не требуются.

Для автоматического прогона остановите backend. Запустите только SITL в отдельном окне PowerShell из корня проекта:

```powershell
New-Item -ItemType Directory -Force .runtime/sitl-state | Out-Null
Push-Location .runtime/sitl-state
..\sitl\ArduCopter.exe --model quad --home 55.755,37.59,150,0 --serial0 tcp:0 --speedup 1
Pop-Location
```

Если SITL уже работает, повторно запускать его не нужно. В другом окне из корня проекта выполните:

```powershell
.\.venv\Scripts\python.exe -m backend.tools.check_sitl
```

Инструмент использует FastAPI TestClient, настоящий worker и настоящий SITL по TCP, временную базу данных и два тестовых плана. Результат сохраняется в `.runtime/sitl-check.json`. По завершении тестовое соединение закрывается; Windows-сборка SITL может завершиться вместе с ним. Перед обычной работой запустите SITL и backend заново. Не подключайте два backend к одному SERIAL0 одновременно.
